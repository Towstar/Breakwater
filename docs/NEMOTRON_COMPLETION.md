## Runtime behavior

- Explicit `validate_run` is idempotent for an immutable run already checked by
  that tool. Its validation reference remains stable. The first explicit check
  after native search still executes independently; search evidence is distinct.
- A repeated eligible validation closes numerical tools after the model's
  existing batch drains. An unstaged workbench run retains an explicit
  model-issued staging opportunity. Successful staging then requests final JSON.
  Required network, control and observation inspection cannot be bypassed.
- EOG closes tools after a cached repeated validation only while that exact
  plan/validation pair remains admissible. A cheaper plan found later in the
  same batch can retire the pair and keep investigation open.
- Missing-coverage investigations can finish after repeating frozen inspection.
  No numerical run is fabricated. Deadlines, call/refinement limits, exact IDs,
  cancellation and the single format-only correction remain enforced.
- The main explanation is assembled from retained numerical evidence, coverage,
  finite-search scope and actual review permissions. Model prose remains an
  explicitly unverified disclosure. Historical EOG records receive the same
  presentation without rewriting the original versioned final event.

These guards reduce repeated completion work. They do not guarantee model prose
accuracy, an optimal response, universal completion, diagnosis or field safety.
The model still chooses tools, arguments, their order and final references.
No response is automatically selected, staged, approved or applied.
